## 3.1 场景与约束模型

**轨道与窗口。** 考虑单颗低轨卫星（可扩展为星座，见 4.9 节）与单个地面站的星地系统。卫星对地面站的可见性由轨道根数决定：给定 TLE，经 SGP4 传播得到星下点轨迹，以最小仰角 ε_min（默认 10°）判据提取过境窗口序列

W = {w_1, w_2, …, w_M}， w_i = (s_i, e_i]，

其中 s_i、e_i 分别为窗口起止时刻。窗口是排他性资源：单天线同一时刻只能建立一条星地链路，窗口之间链路不存在。定义每天可用链路预算

B = Σ_i (e_i − s_i)，

实测 ISS 对单站场景 B ≈ 17–20 min/天（4.1 节），这一物理事实是全文约束的出发点。

**链路服务语义。** 与将链路建模为恒定速率管道的做法不同，本文按"窗口即带宽预算"的排队语义建模：窗口内任务串行占用链路，任务 t 的传输占用时长 τ_tx(t)；若 τ_tx(t) 超出当前窗口剩余时长，任务须排队至下一窗口。该语义下"窗口时长"与"带宽"是同义词，链路受限程度由窗口时长直接刻画（4.3 节扫描即基于此）。

**任务模型。** 任务流 T = {t_1, …, t_N} 按到达过程随机产生，每个任务属性为

t = (a, d, ℓ, x, p)，

其中 a 为到达时刻，d 为截止期（deadline），ℓ 为处理时长（含星上推理与地面推理/传输两部分口径），x ∈ [0,1] 为任务复杂度，p 为优先级（常规/应急）。应急任务带有紧截止期（实验中 1800 s），到达时触发 3.3 节的重规划机制。

**星上能力模型（模糊边界）。** 关键建模假设：星上小模型对任务的"可解性"不是阶跃函数而是 S 形曲线——复杂度 x 的任务被正确解答的概率为

P(correct | x) = σ(k(θ − x))， σ(z) = 1 / (1 + e^{−z})，

θ ∈ [0,1] 为能力阈值（模型"大约会做什么难度的事"），k 为边界锐利度：k→∞ 退化为硬阈值（x≤θ 必对、x>θ 必错），k 有限则边界模糊（θ 附近的任务有时对有时错）。这一形式来自 LLM 小模型的真实行为观察：能力边界从来不是一条清晰的线，而是一条过渡带。4.6 节将表明，边界模糊程度（k 的大小）直接决定置信度路由的收益空间。

**能耗模型。** 能耗是系统中第二种稀缺资源。星上推理功耗 P_on（实验取 15 W）、链路发射功耗 P_tx（取 10 W，均为工程假设值，待 4.8 节实测校准）。任务 t 若星上处理，能耗 E_on(t) = P_on·ℓ_on(t)；若经链路上送，能耗 E_tx(t) = P_tx·τ_tx(t)。系统评价采用"单成功能耗"

E_eff = E_total / N_success，

消除成功率差异的量纲影响（4.7 节）。

## 3.2 星地分层推理架构

系统由星上推理层与地面推理层构成，两层模型能力互补、经稀缺链路耦合。

**星上侧。** 受星载计算平台功耗与显存约束（以 NVIDIA Jetson Orin 级平台为目标），部署经蒸馏的小参数量语言模型（1.5–7B），并以 AWQ 4bit 量化进一步压缩权重显存占用与访存能耗。压缩流水线（基础模型选择 → 任务域蒸馏 → AWQ 量化 → Orin 部署实测）的细节与实测指标（压缩比、单 token 延迟、显存、端到端加速比）在 4.8 节给出。星上模型的职责有两项：一是对任务给出答案，二是输出自评置信度（3.4 节），置信度是连接"模型能力"与"调度决策"的接口。

**地面侧。** 地面站部署 32B 级大模型，采用 vLLM  serving 以获得高吞吐与前缀缓存能力。前缀缓存对本文场景具有结构性意义：智能体工作流的上行 prompt 由共享系统提示前缀（描述角色、工具协议、输出格式）与任务增量组成，前缀在多任务间高度重复，命中缓存后地面侧仅需处理增量部分——这把"链路里塞什么"变成了可优化的系统变量（4.9 节据此讨论与前缀增量传输的互补关系）。

**分层耦合。** 两类任务走两条路径：星上路径（推理 → 置信度判定 → 达标即交付，端到端延迟 ≈ ℓ_on）；地面路径（排队等待窗口 → 上送 → 大模型推理 → 结果回传，端到端延迟 = 排队延迟 + 传输 + 地面推理）。系统的核心问题因此转化为**路由与调度**：每个任务到来时，决策"走哪条路、排在哪个窗口的什么位置"，在成功率、延迟、链路占用、能耗四个目标下取得平衡。

## 3.3 通信窗口感知调度算法

**窗口内排队。** 地面路径的任务进入等待队列 Q。每当窗口 w 开始，按排队纪律从 Q 中选取任务串行服务：最早截止期优先（EDF）或先来先服务（FCFS）。EDF 在任务同权时最小化最大误期，FCFS 作为消融对照（4.2 节表 2）。

**策略 a：朴素路由。** 任务到达时分别估计两条路径的端到端延迟：星上路径延迟即 ℓ_on（若 x ≤ θ）；地面路径延迟按"独占最早可行窗口"的乐观估计（当前窗口剩余时长足够则立即上送，否则排至下一窗口）。星上可行且更快则走星上，否则入队地面。

**策略 b：可行性检查（admit="feasible"）。** 朴素路由的乐观估计忽略了队列竞争：多个任务可能同时乐观地排进同一窗口而溢出。策略 b 在入队前做可行性检查——以当前队列状态模拟服务过程，确认该任务能被某窗口在服务完既有任务后、截止期前完成；不可行则直接判失败（或按优先级另行处理），而不是占用队列位置造成后续阻塞。其本质是把"乐观的局部估计"换成"保守的全局排程"，代价是略高的拒绝率，收益是排队系统的稳定性（4.2 节平均情况、4.5 节最坏情况分别给出其价值的实验证据）。

**应急抢占与可行性再检查。** 应急任务到达时，若当前窗口正在服务常规任务，抢占策略（preempt）令应急任务插队队首。但裸抢占有隐藏代价：被抢占任务的剩余传输可能因此错过截止期，在窗口抖动（概率性丢失）下该代价被放大。本文采用**抢占前可行性再检查**（preempt_feasible）：模拟"抢占发生"后的服务序列，验证被抢占任务能否改排至后续窗口且在截止期前完成；不能则拒绝本次抢占。该机制使抢占从"始终激进"变为"条件激进"——4.5 节表明它把裸抢占 2–3 个点的整体成功率损失完全补回，同时保住 67% 的延迟收益，是抢占机制可工程化的关键。

**算法 1　星地协同任务调度（单窗口服务循环）**

```
输入: 任务流 T，窗口序列 W，能力阈值 θ，置信度阈值 τ
输出: 每任务的处置记录（星上成功/星上误收/地面成功/失败）

for 每个到达任务 t = (a, d, ℓ, x) do
    c ← 星上模型推理并输出置信度            # O(ℓ_on)
    if c ≥ τ 且 a + ℓ_on ≤ d then            # 置信度路由：星上提交
        交付星上答案                          # 误收风险由 τ 控制
    else                                     # 地面升级路径
        ŝ ← 按策略b可行性检查模拟排队          # O(|Q|)
        if ŝ 存在 then 将 t 插入等待队列 Q
        else 记 t 失败
for 每个窗口 w = (s, e] 开启 do
    按 EDF（或 FCFS）从 Q 取任务 t
    while w 剩余时长 ≥ τ_tx(t) do
        服务 t；若完成时刻 ≤ d 记成功，否则记失败
    if 应急任务 t_e 到达 then
        可行性再检查通过 → 抢占队首，否则维持原序
```

调度决策的复杂度为 O(|Q|)（可行性检查需遍历队列一次），置信度判定 O(ℓ_on) 为推理本身开销，无额外算法复杂度；对分钟级窗口、百级任务量的星地场景完全可承受（3.5 节）。

## 3.4 置信度感知路由（方法核心）

硬阈值路由（x ≤ θ 才允许星上提交）隐含两个假设：能力边界是阶跃的（与 3.1 节 σ 曲线矛盾），且"星上能做"等于"星上做对了"（忽略了模型犯错的可能）。置信度感知路由用一个连续量——模型自评置信度 c——同时替换这两个假设。

**置信度模型。** 任务 t 经星上推理得到答案与自评置信度

c(t) = P(correct | x) + b + η，  η ~ N(0, σ_η²)，截断至 [0,1]，

其中 P(correct|x) = σ(k(θ−x)) 为真实答对概率，b 为系统性校准偏置（b>0 过度自信，b<0 不自信），η 为逐次推理的随机扰动。置信度的理想形态是校准的（c 恰等于真实答对概率）；真实小模型往往带偏置，故系统必须在校准误差存在时仍稳健工作（4.6 节三种校准状态即由此构造）。

**路由规则。** 单参数决策：

c(t) ≥ τ → 星上提交答案；c(t) < τ → 升级上送地面大模型。

τ 是系统级整定参数，其语义直观：**τ 是"星上答案可交付"的证据门槛**。τ 降低，更多任务留在星上（省链路、低延迟，但误收增加）；τ 升高，更多任务上送（答案更可靠，但消耗稀缺链路、增加延迟与能耗）。τ 取代 θ 成为系统的"安全旋钮"——θ 是模型的固有属性（换模型才变），τ 是系统的可调属性（运行时即可改），这使"按任务容错要求在线调整系统行为"成为可能。

**误判的两种代价（不对称性）。** 路由错误有两类，代价结构不对称：

- **误收**（false accept）：c ≥ τ 但答案错。代价是交付错误结果——对遥测判读、故障诊断类任务可能是事故级代价；量化指标为每百任务误收数。
- **误升级**（false escalate）：c < τ 但本可星上答对。代价是浪费稀缺链路一次上送机会——在 B ≈ 18 min/天的链路上，这是双重代价（占用窗口 + 挤占其他任务的生存机会）。

不对称性体现在：误收的代价随任务类型变化（可调 τ 控制），误升级的代价随链路稀缺度变化（由场景决定）。链路越稀缺，误升级越贵，最优 τ 应越低——4.6 节的实验精确验证了这一点（链路稀缺 regime 下 τ=0.3 全胜、τ=0.7 多负）。

**多目标性质。** 路由规则诱导出关于 τ 的三目标权衡：

- 成功率随 τ 先微升后降（过低则误收拖累有效成功，过高则链路拥堵）；
- 误收率随 τ 单调下降；
- 单成功能耗在 τ 中部取得极小（4.7 节：τ=0.5 时 0.93 Wh，τ=0.3 时 1.00 Wh，τ 更高则链路能耗占比上升）。

因此不存在全优 τ，只存在给定约束下的帕累托最优 τ：能源紧张型号取 τ≈0.5，任务容错高且链路极稀缺时取 τ≈0.3，高可靠场景取 τ≈0.7 并用其他手段补链路。4.6 节图 5 给出该权衡曲线的完整形态。

**与级联推理（cascade）的关系。** 置信度路由可视为星地两级的级联推理特例：第一级星上小模型" cheap and cheerful"，低置信样本升级至第二级大模型。本文的增量在于：升级通道不是无限带宽的 API 调用，而是受窗口预算约束的物理链路——级联推理的经典结论（升级越多越好）在稀缺链路下不再成立，置信度阈值必须与调度联合设计（3.3 节的策略 b 正是这一联合的落点）。

## 3.5 算法复杂度分析

逐项核算星上在线开销（n 为当前队列长度，N 为任务总量）：

| 环节 | 复杂度 | 说明 |
|---|---|---|
| 置信度路由判定 | O(ℓ_on) | 与星上推理同开销，无额外算法代价 |
| 任务两路径延迟估计 | O(M) | M 为当日窗口数（实测 3–4），可视为 O(1) |
| 可行性检查（策略 b） | O(n) | 模拟队列一次遍历；n 为等待队列长度，窗口串行语义下 n 受带宽预算自然限制 |
| 窗口内服务选择（EDF/FCFS） | O(n log n) | 每次窗口开启排序一次，窗口级频率 |
| 应急抢占再检查 | O(n) | 每应急事件一次，应急为低频事件 |

总在线开销为 O(N·n log n)（全天、窗口级），单决策时刻的开销为 O(n)。对分钟级窗口、百级任务量的场景，n 通常在个位数至数十量级，星上平台（Orin 级）可轻松承受；瓶颈不在算法而在推理本身——这正是 3.2 节压缩流水线要解决的。系统扩展为星座时（4.9 节），窗口并集不改变算法复杂度，仅增大 M，结论不变。
