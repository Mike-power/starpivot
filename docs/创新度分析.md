> **背景**：仿真层 v0.1-v0.5 全部落地（8 组实验数据在手），论文 11 月起稿前需要明确 novelty 定位，避免写成"工程报告"。

## 一、五个相邻领域的全景定位

| 领域 | 代表工作 | 他们做了什么 | 我们的不同 |
|------|---------|-------------|-----------|
| 传统卫星任务调度 | 几十年的运筹学文献（测控资源调度、数传路由） | 调度**数传/成像任务**，无 LLM，无推理质量概念 | 我们调度的是**推理请求**，带质量-延迟权衡和星地质量不对称 |
| 星上 AI / 星地协同推理 | Φ-Sat-1/2、天智星座、DNN split computing / early-exit | 星上跑 CNN，或单层面前切分一个 DNN 前向传播 | 我们是 **LLM Agent 多步任务的任务级路由**，不是单网络层切分；带 deadline 准入控制 |
| LLM 压缩与边缘部署 | AWQ/GPTQ、投机解码、Jetson 部署社区 | 优化**单请求延迟/显存** | 我们的优化目标是**窗口稀缺下的系统级成功率**；压缩是手段，链路占用与 deadline 可行性是一等约束 |
| LLM Agent × 航天 | 2025-2026 新兴方向（LLM 做卫星任务规划、自主运维 Agent） | 多为方案论证级，**无可运行 artifact** | 我们有开源完整系统（github.com/Mike-power/starpivot）+ 真实 TLE + 8 组实验矩阵 |
| 6G/NTN 卫星边缘计算卸载 | 二进制卸载、DNN 分块卸载的通信文献 | 通用计算卸载决策 | 我们面向 LLM 特性：长 prompt、前缀共享、投机解码、置信度升级，加上 Agent 工作流语义 |

**一句话定位**：单点技术都不新（EDF/FCFS/AWQ 都是现成的），**新的是组合**——"LLM Agent × 真实轨道窗口 × 星上压缩推理 × 可复现开源系统"，以及支撑它的系统性实验矩阵。

## 二、诚实短板清单（审稿人/面试官会攻击的点）

1. **调度算法是教科书级**：EDF/FCFS/可行性检查/抢占重规划，单独拿不出手；专利和论文的 claim 必须建在"系统+场景+数据"上，不能建在算法上
2. **任务模型是合成的**：complexity 均匀分布 + 硬阈值 θ，与真实 LLM 行为的关系需要论证（12 月实测是解药，见 L1）
3. **时长简化**：星上处理时长 = 地面时长（scenario.py 已注明），论文需作为建模假设声明
4. **仿真 only**：尚无真实模型数据（12 月 AWQ / 1 月 LoRA 补齐）
5. **核心发现是 observation 不是 method**："链路稀缺是默认状态"是测量结果，论文必须把故事改成"问题驱动"才能上档次（见第四节 framing）

## 三、真正的差异化资产（别人抄不走的）

1. **题材交叉 + 开源完整度**：上述五栏的组合 + 可运行代码，目前公开渠道未见同款
2. **8 组系统性实验矩阵**：排队纪律 × admit 策略 × θ × 应急率 × 丢失率 × 仰角 × 合成/TLE——同类论文通常只有 1-2 组对比
3. **军工航天工程语义**：过境窗口、应急任务、链路预算的理解深度，是论文审稿和面试话语权
4. **θ 扫描的结构性发现**（v0.5 新增）：纯星上(θ) 即天花板且与 θ 线性；协同恒超天花板 +4~6 点；θ≥0.9 链路占用降到 3-4 → "能力-链路替代关系"可以概念化成本文的核心图

## 四、创新度提升杠杆（按性价比排序）

### L1 ⭐ 不确定性感知路由（confidence-aware routing）——下周可动手
把静态硬阈值 θ 换成**运行时置信度判定**：星上小模型产出答案 + 自评置信度（token 熵 / 自洽性 majority vote），置信度 < τ 才升级上送地面。
- **为什么是真创新**：系统从"调度问题"升级为"推理-通信联合优化"；τ 与 θ 的对应、误判代价（错误答案 vs 上送成本）、双阈值设计都有算法含量
- **仿真成本**：1-2 个晚上——给任务一个"真实难度"，置信度 = f(真实难度) + 噪声，可校准复现 θ 硬阈值的行为，再做消融
- **接地路径**：12 月 Jetson 实测直接测真实置信度，仿真抽象立刻变真实数据，正面回应短板 2
- **专利价值**：权利要求可写"基于模型输出置信度的星地动态分层推理方法"，比"调度方法"硬一档

### L2 Agent 工作流内容感知传输（前缀缓存 + 增量上送）——11 月做
任务 prompt = 共享系统前缀 + 任务增量；窗口内只传增量，地面 vLLM 前缀缓存命中，处理时长下降。
- 建模改动：duration 拆成 prefix + delta；链路占用从"任务数"升级为"字节数"，带宽节省可量化
- 对接创新点③（Agent 工作流前缀缓存复用），论文可单列一节，是"LLM 特性"差异的直接物证

### L3 能耗/热约束维度——一个下午
星上推理耗能 vs 下行耗能权衡，Metrics 加能耗列。《航天器工程》读者关心功耗预算，工程深度加分。

### L4 多星组网——12 月视时间
单 ISS → 星座（多 TLE 合并时间线），窗口池化 + 跨星调度，给出成功率的星座级 scaling 曲线。论文展望落地或第二篇素材。

### L5 在线学习自适应 τ / RL 调度——不建议现在做
过度工程，投中文核心性价比低；除非后期改冲更高刊物。

## 五、Framing 升级：从"系统"到"问题"

论文故事线改法：

- ❌ 旧："我们设计了一个星地协同推理系统"（系统驱动，像工程报告）
- ✅ 新："**链路稀缺 regime 下，星上推理能力的系统级价值是多少？**"（问题驱动）
  - 答案 1：纯星上(θ) 是天花板且与 θ 线性（v0.5 扫描）
  - 答案 2：分层协同严格优于任何单一阵营（恒超天花板 +4~6 点）
  - 答案 3：能力-链路存在替代关系（θ↑ → 链路占用 6→3）
  - 方法（调度、准入、抢占）变成"回答问题的工具"，创新点①②③自然嵌入

## 七、对三条线的意义

- **论文**：L1 让方法章有算法含量，framing 升级让引言有"问题"，θ 扫描让讨论有"洞察"——三处都是审稿人给分的点

- **跳槽面试**："我们发现并量化了能力-链路替代关系"比"我搭了个系统"高一个叙事层级，是项目深挖环节的杀招
