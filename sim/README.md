# sim/ —— 星座任务仿真环境

「星枢」的实验数据来源：在地面复现"通信窗口受限 + 星上算力受限"的约束，让三种方案（纯星上 / 纯地面 / 星地协同）在同一场景下可比。

## 当前进度：v0.3 排队感知版（2026.9.25）

- ✅ 任务模型（任务 / 紧急度 / 复杂度）
- ✅ 合成通信窗口 + **链路容量约束**（窗口槽位有限，find/commit 两步预约）
- ✅ 两个极端基线：纯地面方案、纯星上方案
- ✅ **星地协同贪心策略 v0.2**：每个任务比较"地面窗口预约"与"星上硬解"的端到端延迟，取可行且快者
- ✅ **参数扫描实验框架**（`experiments.py`）：多种子 × 多场景，结果写入 `benchmark/results/`
- ✅ **TLE 真实轨道接入**（`timeline_tle.py` + `run_tle.py`）：CelesTrak 公开 TLE（默认 ISS），
  纯 sgp4 传播 + GMST 近似坐标转换，不依赖大型历表文件，国内可离线复现。
  已用多仰角阈值交叉验证（0°/5°/10° → 7/5/3 次每天过境，与公开统计一致）。

关键实验结论（5 种子均值，100 任务/场景）：链路受限（窗口容量 4）时，
纯地面方案成功率从 97% 崩至 39%~86%，星地协同保持 70%~97%——
**链路越受限、过境越稀疏，协同优势越大**（完整数据见 `benchmark/results/sweep_v0.2.md`）。

TLE 真实场景（ISS 过境 3 次/天、链路容量 4）：纯地面成功率仅 11%，
星地协同 47%——比合成场景更极端，真实世界的故事更有冲击力
（数据见 `benchmark/results/tle_iss.md`）。

TLE + 排队模型（论文主实验，`run_tle_queued.py`，5 种子均值）：
真实过境窗口每天累计仅约 20 分钟带宽，却要承载 100 个任务——
纯地面崩溃至 **3%**，星地协同守住 **33%**
（数据见 `benchmark/results/tle_iss_queued.md`）。
这个场景把发现 4 推到极致：**链路稀缺不是假设，是真实星地链路的默认状态**，
星上推理能力是系统成立的前提。

v0.3 排队感知（串行服务 + 选槽策略，100 任务合成场景）：

| 策略 | 成功率 | 平均延迟 |
|---|---|---|
| 纯地面+EDF | 22% | 15149s |
| 协同 v0.3a（朴素 EDF） | 71% | 5729s |
| 协同 v0.3a（FCFS，消融） | 74% | 5914s |
| 协同 v0.3b（EDF + 可行性检查） | **79%** | 6138s |
| 协同 v0.3b（FCFS + 可行性检查） | **79%** | **4779s** |

两个可直接写进论文的发现：
1. **朴素 EDF 可能输给 FCFS**——截止期过紧的任务即使优先也是必死，
   还白占带宽；加上"可行性检查"（必死任务快速失败不占槽）后成功率提升 5-8 个点；
2. **选槽策略存在目标权衡**——EDF+可行性偏成功率，FCFS+可行性偏延迟，
   调度策略应按任务负载特征自适应选择（后续工作方向）。

v0.3 已接入参数扫描（`experiments.py`：period × 窗口时长双因素 × 5 种子，
完整数据 `benchmark/results/sweep_v0.3.md`）。新发现：

3. **链路越受限，可行性检查收益越大**——5 分钟窗口（带宽最紧）下，
   协同 a→b 提升约 19 个点（34%→49%@1.5h 周期）；窗口充足（15min）时两者持平，
   说明可行性检查是为" scarcity regime "设计的机制；
4. **极端受限链路下纯地面崩溃、星上兜底的价值显现**——5min 窗口时
   纯地面仅 3~14%，协同方案保住 33~61%：星上推理不是"可选项"，是
   链路稀缺时的生存底座。

- ✅ **v0.4 应急重规划骨架**（`emergency.py` + `run_emergency.py`，事件驱动在线调度；
  应急插入/窗口丢失/窗口抖动三类事件，static/preempt/preempt_feasible 三策略消融，
  结果见 `benchmark/results/emergency_v0.4.md`）：
  - 抢占+可行性较静态基线应急成功率 +12 点（10% 应急率、20% 丢失率：38%→50%），假设 1 方向成立；
  - **可行性检查是承重机制**：单纯抢占（无可行性）整体成功率反降 16~19 点（复现 v0.3a 行为）；
  - 抢占对常规任务代价 ≈ 0（preempt_feasible 与静态整体成功率持平），假设 2 成立；
  - 应急成功率天花板 ≈56%：应急 deadline 1800s ≪ 过境周期 90min，**应急任务大多必须星上硬解**——
    这是「星上能力是生存底座」最尖锐的实验证据。
- ✅ **v0.4 × TLE 真实轨道**（`run_tle_emergency.py`，论文实验完整版，
  结果见 `benchmark/results/tle_emergency.md`）：合成场景结论在真实轨道下全部复现——
  抢占+可行性在应急成功率上全面 ≥ 静态基线（+2~5 点），单纯抢占整体成功率仍略差；
  真实轨道把应急成功率压到 25~32%（合成场景 56% 天花板的一半），
  **轨道越真实，应急越只能靠星上**——动态重规划机制与星上能力互为表里，缺一不可。

## 运行

```bash
python sim/main.py          # 三方案对比（无限链路对照组 + 受限链路实验组）
python sim/experiments.py --save   # 参数扫描，结果落盘 benchmark/results/
```

## 设计说明

- **复杂度阈值**模拟"星上只能处理简单任务"：任务复杂度 ≤ 阈值才允许星上硬解，这是星地协同策略要动态决策的变量
- 随机种子固定，保证每次运行结果可比、实验可复现
