# sim/ —— 星座任务仿真环境

「星枢」的实验数据来源：在地面复现"通信窗口受限 + 星上算力受限"的约束，让三种方案（纯星上 / 纯地面 / 星地协同）在同一场景下可比。

## 当前进度：v0.9 推理延迟耦合版（2026.9.30）

- ✅ 任务模型（任务 / 紧急度 / 复杂度）
- ✅ 合成通信窗口 + **链路容量约束**（窗口槽位有限，find/commit 两步预约）
- ✅ 两个极端基线：纯地面方案、纯星上方案
- ✅ **星地协同贪心策略 v0.2**：每个任务比较"地面窗口预约"与"星上硬解"的端到端延迟，取可行且快者
- ✅ **参数扫描实验框架**（`experiments.py`）：多种子 × 多场景，结果写入 `benchmark/results/`
- ✅ **TLE 真实轨道接入**（`timeline_tle.py` + `run_tle.py`）：CelesTrak 公开 TLE（默认 ISS），
  纯 sgp4 传播 + GMST 近似坐标转换，不依赖大型历表文件，国内可离线复现。
  已用多仰角阈值交叉验证（0°/5°/10° → 7/5/3 次每天过境，与公开统计一致）。

关键实验结论（5 种子均值，100 任务/场景）：链路受限（窗口容量 4）时，
纯地面方案成功率从 97% 崩至 39%~86%，星地协同保持 70%~97%——
**链路越受限、过境越稀疏，协同优势越大**（完整数据见 `benchmark/results/sweep_v0.2.md`）。

TLE 真实场景（ISS 过境 3 次/天、链路容量 4）：纯地面成功率仅 11%，
星地协同 47%——比合成场景更极端，真实世界的故事更有冲击力
（数据见 `benchmark/results/tle_iss.md`）。

TLE + 排队模型（论文主实验，`run_tle_queued.py`，5 种子均值）：
真实过境窗口每天累计仅约 20 分钟带宽，却要承载 100 个任务——
纯地面崩溃至 **3%**，星地协同守住 **33%**
（数据见 `benchmark/results/tle_iss_queued.md`）。
这个场景把发现 4 推到极致：**链路稀缺不是假设，是真实星地链路的默认状态**，
星上推理能力是系统成立的前提。

v0.3 排队感知（串行服务 + 选槽策略，100 任务合成场景）：

| 策略 | 成功率 | 平均延迟 |
|---|---|---|
| 纯地面+EDF | 22% | 15149s |
| 协同 v0.3a（朴素 EDF） | 71% | 5729s |
| 协同 v0.3a（FCFS，消融） | 74% | 5914s |
| 协同 v0.3b（EDF + 可行性检查） | **79%** | 6138s |
| 协同 v0.3b（FCFS + 可行性检查） | **79%** | **4779s** |

两个可直接写进论文的发现：
1. **朴素 EDF 可能输给 FCFS**——截止期过紧的任务即使优先也是必死，
   还白占带宽；加上"可行性检查"（必死任务快速失败不占槽）后成功率提升 5-8 个点；
2. **选槽策略存在目标权衡**——EDF+可行性偏成功率，FCFS+可行性偏延迟，
   调度策略应按任务负载特征自适应选择（后续工作方向）。

v0.3 已接入参数扫描（`experiments.py`：period × 窗口时长双因素 × 5 种子，
完整数据 `benchmark/results/sweep_v0.3.md`）。新发现：

3. **链路越受限，可行性检查收益越大**——5 分钟窗口（带宽最紧）下，
   协同 a→b 提升约 19 个点（34%→49%@1.5h 周期）；窗口充足（15min）时两者持平，

- ✅ **v0.6 不确定性感知路由**（`confidence.py` + `run_confidence_sweep.py`，
  创新度杠杆 L1，结果见 `benchmark/results/confidence_sweep.md`）：
  把路由判据从硬阈值 θ 换成运行时置信度——小模型给出 (答案, 自评置信度 c)，
  c ≥ τ 提交星上答案，c < τ 升级地面排队。概率模型：答对概率 σ(k(θ−x))，
  置信度 = 答对概率 + bias + 噪声（bias=0 校准 / +0.15 过度自信 / −0.15 不自信），
  同一 (正确性, 置信度) 实现按种子全策略共享，差异只来自策略。五个发现：
  1. **链路极稀缺 regime 下"升级上送"期望收益趋零，低 τ 反而成功率高**：
     τ=0.3 在全部 6 个边界×校准格中胜率最高（较硬阈值 +1.0~+10.8 点）——
     敢赌的中间难度任务若送去排队几乎必死，星上博一把期望值为正；
  2. **成功率与安全性构成 τ 的多目标权衡**：低 τ 的代价是误收错误答案
     （每 100 任务 12.8→36.4 个），论文必须把误收率列为独立安全指标，
     不能只看成功率；
  3. **能力边界越模糊，置信度路由相对硬阈值的收益越大**
     （校准场景 +3.4%@k=10 → +6.4%@k=5）——定量证明硬阈值在模糊边界下
     系统性浪费能力，这正是 LLM 小模型的真实形态；
  4. **过度自信的损害可被高 τ 部分补偿，系统退化平滑**：
     k=10 下 τ=0.7 把误收从 22.8 压到 5.6，成功率仅 -6.6 点；
  5. **校准良好时 τ=0.5 是稳健折中**：成功率 ≈ 硬阈值（+0.0~+0.8），
     误收仅 6.6~10.4，工程部署的默认推荐值。
  边界声明：本实验 regime 为链路极稀缺（纯地面仅 5%）；链路充足 regime
  （如 sweep_v0.3 的 15min 窗口）下最优 τ 预计移向保守端，列为后续工作。

- ✅ **L2 前缀增量传输**（`run_prefix_l2.py` + `queueing._tx_time`，
  创新度杠杆 L2，结果见 `benchmark/results/prefix_l2.md`）：
  Agent 工作流上行 payload = 共享系统提示前缀（60s 假设）+ 任务增量
  （10-40s）；地面前缀缓存命中后只传增量（cache dict 兼作命中统计）。
  两场景 × 两策略 × 开关对比，四个发现：
  1. **成功率飞跃**：TLE 协同 b 37%→60%（+23 点）、合成稀缺 53%→92%（+39 点）；
     纯地面 TLE 5%→39%——前缀复用把"链路里塞什么"变成了系统主杠杆；
  2. **链路秒数 -72%~-81%**（TLE 协同 2969s→826s）——缓存命中后单任务
     传输从均值 165s 降到 ~25s，等效带宽扩容 5-6 倍；
  3. **机制**：全场仅 1 次未命中（首个上行任务付全量前缀），此后全命中——
     "一次前缀，全天复用"是 Agent 工作流上行的结构性红利；
  4. 与 v0.5 能力-链路替代互补：**θ 抬天花板（能做多少），L2 扩链路
     （能传多少）**——系统两个瓶颈各有一个对应机制。
  口径声明：前缀/增量秒数为假设值（真实值待 ground 侧 vLLM 实测校准）；
  prefix_cfg 改变了 RNG 流，基线行与 v0.5-v0.7 实验的绝对值略有差异，
  格内对比（同任务集同种子）严格公平。

- ✅ **L4 多星组网**（`timeline_constellation.py` + `run_constellation_l4.py`，
  创新度杠杆 L4，结果见 `benchmark/results/constellation_l4.md`）：
  以真实 TLE 为基准做平近点角 360°/N 等相位偏移，合成 N 星同轨道面星座
  （Walker 式相位偏移思想，非真实多轨道面星座，论文需声明）；
  单地面站受单天线约束，对所有星过境窗口取并集（重叠合并）池化使用。
  N ∈ {1,2,4,8} × 协同b-EDF可行，四个发现：
  1. **成功率随星数单调爬升且未饱和**：33%→39%→48%→63%（N=1→8），
     纯星上天花板仅 26%——组网让协同策略持续跑赢纯星上；
  2. **链路资源近线性扩容**：窗口 3→29 次/天、累计带宽 18→152 分钟/天
     （≈8.4 倍），但成功率只 +30 点——瓶颈从"有没有窗口"转向
     "任务产生时刻与窗口的相位对齐"，scaling 收益递减；
  3. **延迟先升后降**（2959s→5790s→5108s）：星数少时任务等不到窗口直接
     失败（失败任务不计延迟），星数多时窗口密、排队短——延迟下降是
     成功率上升的镜像；
  4. **组网与前缀缓存互补**：N=8 带宽 ×8.4 叠加 L2 传输压缩 -72%，
     "扩窗口"与"省窗口内的秒数"是两条正交链路杠杆。
  口径声明：星座为相位偏移合成（同轨道面），非真实星座设计；
  窗口并集假设单天线同时只能跟踪一星（保守假设）。

- ✅ **v0.8 Agent 多步工作流**（`agentflow.py` + `run_agentflow.py`，
  结果见 `benchmark/results/agentflow_v0.8.md`）：
  把任务从单步问答升级为多步工作流（3 步，串行依赖，all-or-nothing
  交付），事件驱动引擎：步骤就绪链（地面步完成时刻触发下一步）、
  逐 steps 置信度路由、跨 workflow 共享系统前缀（L2 缓存跨步复用）。
  50 工作流 × 3 步 × 5 种子，TLE 真实轨道，四个发现：
  1. **交付语义是 τ 整定的第三变量（本实验最重要的发现）**：单任务层
     "低 τ 敢赌全胜"的结论（4.6 节）在 all-or-nothing 工作流下被**反转**——
     任一步误收杀死整个工作流，误收代价按步数指数放大
     （P(存活) = Π(1−误收率ᵢ)），τ=0.3 时 50 个工作流约 30 个死于误收；
  2. **工作流成功率受"链路预算 ÷ 步数"硬约束**：18 min/天带宽 ÷ 每步
     25s 增量 ≈ 43 步上限，50 个工作流需 75-150 步——成功率天花板
     由步数与链路预算的商决定，τ 只能在这个天花板下微调；
  3. **前缀复用机制独立成立**：全部工作流共享同一智能体应用前缀，
     命中 40+ : 未命中 1——"一次前缀，全天复用"从单任务红利升级为
     工作流红利，与 τ、步数均无关；
  4. **省链路秒数直接兑换成完成数**：缓存关闭时未完工工作流 4 → 14，
     省下的秒数让更多的步骤挤进同一带宽预算。
  5. **步级补偿 × 组网是超可加组合**（v0.8c 联合实验，
     `run_agentflow_constellation.py`，结果见 agentflow_constellation.md）：
     补偿在单星把误收死亡清零（13→0）但成功率只 18%→20%——药房满没满
     取决于窗口；星座把窗口 ×8.4 后，τ=0.3 下成功率 57%→**85%**
     （+28 点，远超补偿单独 +2 与组网单独 +39 的简单相加）——
     **重试步需要第二次窗口机会，组网给它这个机会**；且有了补偿兜底，
     τ=0.3（敢赌）与 τ=0.5（保守）在 N=8 处收敛同分（85%）：
     "敢赌的代价被补偿机制清零"。建模修正：地面大模型答案视为正确
     （profile.correct 是星上小模型实现，不可套用于地面步）。
  口径声明：all-or-nothing 为保守语义；步骤延迟/前缀秒数为假设值。

- ✅ **v0.9 TTFT/TPOT 真实推理延迟耦合**（`inference.py` +
  `run_inference_l6.py`，创新点③的下半篇，结果见
  `benchmark/results/inference_l6.md`）：
  v0.3-v0.8 的黑箱假设"传输耗时 = 任务时长、地面推理瞬间完成"被拆开：
  地面处理 = 链路传输（prefix+delta token，占窗口带宽）+ TTFT（prefill，
  输入长度驱动）+ TPOT（decode，输出长度驱动；prefill/decode 在窗口后
  地面计算，不占带宽但计入完成时刻）。`serve_fn` 可插拔注入
  `_serve_pending` / `star_ground_coop_queued`，默认 None 时行为与
  v0.3-v0.8 逐字节一致（回归验证：`run_tle_queued.py` 协同 b-EDF可行
  仍为 33%）。三行对比（TLE、100 任务 × 5 种子、协同 b-EDF可行、
  L2 prefix_cfg 任务）：
  | 服务耗时口径 | 成功率 | 平均延迟 | 链路占用 |
  |---|---|---|---|
  | ① duration 黑箱基线 | 38% | 3376s | 6 |
  | ② TTFT/TPOT 无缓存 | 69% | 5917s | 38 |
  | ③ TTFT/TPOT + L2前缀缓存 | 69% | 5125s | 38 |
  四个发现：
  1. **token 口径天然解耦带宽与算力，成功率不降反升（38%→69%）**——
     duration 黑箱把 30-300s 的"处理时长"全记在链路头上，token 口径下
     上行仅 (200-2000)/50 ≈ 4-40s，窗口带宽压力骤降；prefill/decode
     移出带宽约束后不再挤占窗口——**窗口占用与任务延迟解耦**正是本版
     建模特征，也是相对 v0.3-v0.8 最重要的语义修正；
  2. **前缀缓存红利翻倍兑现**：L2 在 v0.3-v0.8 只统计了"省链路秒数"，
     本实验补上另一半"省 prefill 计算"——命中时 prefill 只算 delta
     部分，平均延迟 5917s→5125s（-13%），链路传输与 prefill 计算
     双降，创新点③的完整收益至此闭环；
  3. **成功率口径下缓存红利被可行性准入掩盖，延迟口径才看得见**——
     ②③成功率同为 69%（feasible 准入把必超时任务提前杀掉，缓存省下的
     秒数不改变生死线），但活下来的任务明显更快；论文应以双口径报告
     L2 收益，单看成功率会系统性低估前缀缓存；
  4. **延迟上升不是退化，是语义诚实的代价**：5917s > 3376s 是因为
     黑箱口径把地面推理记成了 0，token 口径把 TTFT+TPOT 如实计入
     端到端延迟——绝对值与 v0.3-v0.8 不可比，格内对比才有效。
  口径声明：TX 50 / PREFILL 1000 / DECODE 20 tok/s 为工程假设值，
  待 2026.12 AWQ 实测校准；input ~ U(200,2000)、output ~ U(50,500)，
  前缀 token 占比按 tx_prefix/tx_delta 链路耗时占比拆分；
  assign_tokens 用独立随机流（seed+40000），不触碰 gen_tasks 的 RNG
  流（v0.3-v0.8 基线可复现性保障）。
